# CMS Guard Lite 설계

직원용 CMS의 지정된 테스트 문서·파일·기능에 대한 권한 검증을 재현 가능한 연구 프로젝트로 만든다. 인터넷에서 접속 가능한 CMS도 HTTPS 대상 목록에 넣어 검사할 수 있다. 실제 회사 주소·문서·계정은 소스에 포함하지 않고 개발 중 접속하지 않는다.

PentAGI의 작업→실행→증거→보고 구조를 참고한 독립 구현이다. PentAGI 포크 또는 기능 동등품이 아니다. Python 3.11+ 표준 라이브러리만 사용한다. PostgreSQL, Redis, 브라우저, 셸 실행, 멀티 에이전트 상시 구동은 필요 없다. 선택적인 로컬 LLM은 검증된 결과의 집계만 요약하며 요청이나 판정을 생성하지 않는다.

## 구성
- config.py: JSON 작업·역할·정확한 URL 목록 검증. 인증 값은 환경 변수에서만 읽는다.
- transport.py: TLS 검증, DNS 해석 후 IP 고정 연결, 범위 제한, 리다이렉트 금지, 요청/시간/응답 크기 제한.
- engine.py: 허용 계정의 양성 대조군 + 비허용 계정 비교. HTTP 200만으로 성공을 판정하지 않고 가짜 문서의 고유 표식을 확인한다. 세션은 활성 토큰과 관리자가 무효화한 이전 토큰을 비교한다.
- audit.py: DB·SSO·파일 정책의 제공된 설정 스냅샷 검토. 실제 동작 확인과 구분한다.
- lab.py: 루프백 전용 고정/취약 모드 실험 서버. 무해한 업로드와 텍스트 escaping 검증.
- report.py: JSON/Markdown/한국어 HTML 대시보드. 원문·URL·인증 헤더·canary를 기록하지 않는다.
- llm.py: 선택적 루프백 OpenAI 호환 API 요약. 집계만 전달하며 외부 서비스 연결은 제공하지 않는다.
- benchmark.py: 정답이 있는 로컬 실험을 반복하고 탐지율·정밀도·시간·요청 수 기록.

## 경계와 판정
운영 HTTPS 대상은 GET만 허용한다. 정확한 URL만 요청하며 링크 수집·ID 열거·비밀번호 추측·익스플로잇은 하지 않는다. GET에도 부작용이 있을 수 있으므로 조회 전용 테스트 리소스를 지정한다. POST는 동봉한 루프백 실험 프로토콜의 업로드/렌더 두 경로만 허용한다. SSO 로그인·MFA 자동화는 포함하지 않는다.

pass는 지정 사례의 기대 동작 확인, fail은 기대 위반, inconclusive는 근거 부족, error는 실행 실패, manual은 입력 부재다. 서비스 전체 안전을 보장하지 않는다. 권한 거부 성공은 같은 리소스에 대한 양성 대조군이 성공해야 인정한다. 무효화 토큰은 실행자가 전후 상태를 준비해야 한다.

기본 제한: 100 HTTP 요청, 전체 120초, 요청 5초, 응답 64 KiB, 초당 최대 2요청. HTTPS는 공인 IP만 기본 허용하며 사설망은 명시 CIDR로 추가할 수 있다. 메타데이터/link-local/multicast/unspecified 주소는 차단한다. 원문은 메모리에서만 표식 판정 후 폐기한다. 설정 파일과 보고서는 소유자 권한으로 저장한다.

## 검증
실제 HTTP 서버를 사용하는 통합 테스트: 정상/취약 권한, 로그인 페이지 200, redirect 미추적, 양성 대조군 실패, 누락 인증, 읽기 상한, 예산, 정확한 범위, 사설 IP 제한, 인증 정보 비기록, HTML escaping, 로컬 업로드/입력, 설정 audit unknown, benchmark 정답 비교. 회사 서비스에 대한 테스트는 수행하지 않는다.
